# 第一次加入：做一次，以后直接和 AI 聊

## 项目负责人

1. 保持仓库 Private，不启用公开 Pages。确认要加入的是有权访问课程资料的真实组员。
2. 获得组员 GitHub 用户名后，通过仓库 Settings → Collaborators 发邀请，组员自己接受。不要共享账号。
3. 在 `project/config.json` 的 `members` 中将 A/C 的 null 换成各自用户名；每个用户名只绑定一个角色。可通过代码变更流程记录调整。
4. 若改变起始服务或数据库，将理由记入 `docs/decisions.md` 并更新配置；不要让各人的 AI 自行选不同方案。

## 每位组员

1. 用自己的 GitHub 账号接受仓库邀请，确认能打开 README 和 Issues。
2. 在自己的 AI 工具中连接 GitHub，授权读取/更新这个仓库，或者打开克隆到自己电脑的副本并配置本人正常的 GitHub 操作方式。无需向本仓库提交任何 AI API key。
3. 把 `prompts/START.md` 的首次开场语给 AI，填写自己的 GitHub 用户名。AI 应报告从配置读到的角色。
4. 让 AI 读取最新任务卡并发认领命令；看到系统回执再开始。若无法评论，先解决连接权限，而不是让别人代签。
5. 有 AWS 访问权限才实际操作；否则与最终环境持有人约共享屏幕，提交步骤并共同验证。

## 只有聊天、没有 GitHub 工具时

AI 可以解释任务，但不能自动同步。由本人把 AI 给出的命令复制到任务评论，并把真实回执交给 AI；文件仍需本人上传。不要声称普通聊天能仅凭一个 private 链接自动管理仓库。
