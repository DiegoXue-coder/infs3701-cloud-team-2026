# 优先检查：三个人能否分别登录同一课程 Lab

状态：**待登录实际 AWS 环境核对，尚无结论，未创建账号或更改权限。**

用户于 2026-10-31 要求先确认多人直接访问能力，再决定环境协作方式。应用已选 Reading Tracker；本地开发和配置准备仍可并行，但共享 AWS 身份与权限配置需先完成此检查。

## 已有证据及边界

- 当前工具没有 AWS 环境变量、CLI 凭证或本机 AWS 配置；已打开 AWS Academy 学生登录页，等待本人登录。
- Week 5 tutorial 第 11 页明确写 Lab 不允许创建新 roles/policies；这是课程限制证据，不等同已经实测 iam:CreateUser 的结果。
- 不能仅凭看到 IAM 菜单或 Create user 按钮就认定创建与授权可成功；也不能通过创建管理员账号来测试权限。

## 登录后按顺序检查

1. 确认实际是 AWS Academy Learner Lab、所在区域和当前登录身份；不要把 EC2 的 LabRole 当成组员的登录账号。
2. 读取 Lab 的服务/身份限制及课程的多人协作规则，确认是否允许其他组员访问此账户。
3. 检查当前身份是否可建立人类登录身份及授予所需权限。IAM 用户路线涉及 CreateUser、CreateLoginProfile、组/策略绑定及相关边界；联合身份/邀请路线按环境实际提供的功能核对。
4. 若允许且课程规则允许，准备两位组员的独立身份、职责权限及首次登录方式的具体配置方案。只给必要权限，不默认全管理员。
5. 如果策略模拟器可用，可作只读辅助检查；模拟结果不保证实际环境和课程规则允许，不据此绕过 Lab 限制。
6. 准备好方案后再配置真实访问，并由每位本人验证登录、允许的操作及禁止的操作。

## 账号与密码交付

按实际支持方式处理：优先本人接受邀请或使用独立临时身份；若只能使用 IAM 用户的初始密码流程，采用临时密码并要求首次登录更改。凭证不写入 GitHub、执行日志或课程共享材料，不共用主账号。当前未生成任何密码。

## 结果如何记录

只记录非敏感的允许/拒绝结论、依据、检查时间、身份类型和错误；账号 ID/身份 ARN 如需归档应先按用途去敏。读不到权限时记“无法确认”，不能把访问失败猜成所有操作都不允许。

如果不支持，由 tutor 提供允许的小组环境/授权办法；此前的脚本与共享屏幕方案只是可讨论替代，不能在没有核对时宣称它是唯一方案。
